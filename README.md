# SiteCAD — 자연어로 작업하는 로컬 CAD

SiteCAD는 OpenCADStudio 편집기와 AI·MCP를 연결하는 macOS(M계열)·Windows 로컬 브라우저 앱입니다. AI 계정을 연결한 뒤 채팅으로 2D 도면과 지원되는 3D 형상을 만들고 수정하거나 물량을 검토하고 DWG로 저장합니다. CAD 파일 처리와 도구 실행은 내 PC에서 이루어지며 AI 요청은 온라인 서비스를 사용합니다.

**[0.16.0 설치 파일 — GitHub Actions](https://github.com/seominpapa/SiteCAD/actions/workflows/windows.yml)** · [공개 릴리스](https://github.com/seominpapa/SiteCAD/releases/latest) · [소스와 빌드 정보](SOURCE_BUILD.md)

## 다운로드와 버전 확인

**현재 소스 버전은 0.16.0입니다.** 2026-11-03 확인 기준 공개 Releases에는 0.15.0 웹앱 ZIP이 있고, 0.16.0 웹앱 ZIP·데스크탑 설치 파일은 GitHub Actions에서 제공합니다. 코드가 업데이트되어도 이미 내려받은 파일이나 공개 릴리스가 자동으로 바뀌지는 않습니다. 아래 기능 안내는 0.16.0 소스 기준입니다.

| 사용 방식 | 대상 | 받을 파일 | 실행 방식 |
| --- | --- | --- | --- |
| 웹앱 | Mac M계열 | `SiteCAD-0.16.0-local-web-macOS.zip` | 압축을 풀고 `Start SiteCAD.command` 실행 |
| 웹앱 | Windows 10/11 64비트 | `SiteCAD-0.16.0-local-web-Windows.zip` | 모두 압축을 풀고 `Start SiteCAD.cmd` 실행 |
| 데스크탑 | Mac M계열 | `SiteCAD-0.16.0-macOS-arm64.dmg` | `SiteCAD.app`을 응용 프로그램에 복사 |
| 데스크탑 | Windows x64 | `SiteCAD-0.16.0-Windows-x64-Setup.exe` | 설치 마법사로 설치 |

웹앱은 기본 브라우저와 실행기 터미널을 함께 사용하고, 데스크탑은 전용 앱 창에서 사용합니다. 두 방식 모두 내 PC에서 로컬 서비스와 CAD 도구를 실행합니다. 별도 원격 서버를 준비할 필요는 없으며, 로컬 접속 주소는 다른 사용자를 위한 공개 서비스 주소가 아닙니다.

### GitHub Actions에서 0.16.0 받기

1. GitHub에 로그인한 뒤 [설치 파일 생성 작업](https://github.com/seominpapa/SiteCAD/actions/workflows/windows.yml)을 엽니다.
2. `main` 브랜치의 작업 중 **Windows와 macOS 검사가 모두 초록색으로 완료된 실행**을 선택합니다. 실행 중이거나 실패한 작업의 파일은 사용하지 마세요.
3. 실행 결과 아래 **Artifacts**에서 Windows는 `SiteCAD-Windows-…`, Mac은 `SiteCAD-macOS-…`를 다운로드합니다. 끝의 긴 문자열은 파일을 만든 소스 버전 식별자입니다.
4. 내려받은 Artifacts ZIP을 먼저 풉니다. 그 안에서 위 표의 **웹앱 ZIP 또는 데스크탑 설치 파일 하나**를 선택합니다. 웹앱을 선택했다면 안쪽 웹앱 ZIP도 별도 폴더에 풀어야 합니다. `verification/`에는 해당 빌드의 검사 기록이 있습니다.

Actions 파일은 생성 후 **14일간 보관**합니다. 다운로드가 만료되면 더 최근에 성공한 작업을 확인하세요. 새 성공 작업도 없다면 소스에서 빌드하거나 새 빌드를 요청해야 합니다. GitHub의 **Code → Download ZIP**이나 릴리스의 자동 생성 **Source code.zip**은 위 설치 파일과 다릅니다.

이전 공개 0.15.0이 필요한 경우: [Windows 웹앱 ZIP](https://github.com/seominpapa/SiteCAD/releases/download/v0.15.0/SiteCAD-0.15.0-local-web-Windows.zip) · [Mac 웹앱 ZIP](https://github.com/seominpapa/SiteCAD/releases/download/v0.15.0/SiteCAD-0.15.0-local-web-macOS.zip). 0.16.0의 통합 설정 등 새 기능은 이 파일에 포함된 것으로 가정하지 마세요.

## 웹앱 설치와 실행

최초 설치에는 인터넷과 폴더 쓰기 권한이 필요합니다. Git·Homebrew·전역 Node.js·전역 Codex를 미리 설치할 필요는 없습니다. 실행기가 전용 Node.js 24.22.1, 운영 의존성, Codex 0.163.0을 준비하며 다음 실행부터 재사용합니다. AI 요청과 외부 API·MCP를 사용할 때는 해당 서비스에 접속할 수 있어야 합니다. Linux 자동 실행기는 제공하지 않습니다.

### Mac M계열

1. 위 다운로드 절차에서 `SiteCAD-0.16.0-local-web-macOS.zip`을 받습니다.
2. ZIP을 풀고 안의 `SiteCAD` 폴더 전체를 문서 폴더 등 **본인이 쓸 수 있는 위치**에 둡니다. 실행 파일만 따로 옮기지 마세요.
3. `SiteCAD` 폴더의 **`Start SiteCAD.command`**를 더블클릭합니다. 터미널이 열리고 최초 준비가 진행됩니다. 완료될 때까지 창을 유지합니다.
4. 자동으로 열린 기본 브라우저에서 CAD 화면이 준비될 때까지 기다립니다. 브라우저가 열리지 않으면 터미널에 표시된 `http://127.0.0.1:숫자/` 주소로 접속합니다. 포트 번호는 실행 시 정해지므로 예전 주소로 고정하지 마세요.
5. 처음에는 **설정 → 일반 → 폴더 선택**으로 저장 위치를 확인하고, AI를 쓰려면 [AI 연결](#처음-ai-연결)을 진행합니다.

macOS가 실행을 차단하면 파일 출처를 확인하고 **시스템 설정 → 개인정보 보호 및 보안**의 안내에 따라 직접 허용합니다. 키체인·폴더 접근 권한 요청도 사용자가 확인합니다. 출처 경고를 일괄 해제하는 명령은 실행기가 자동으로 적용하지 않습니다.

### Windows

1. `SiteCAD-0.16.0-local-web-Windows.zip`을 받습니다.
2. 파일 탐색기에서 ZIP을 우클릭해 **모두 압축 풀기**를 선택합니다. 문서 폴더 등 쓰기 가능한 위치에 전체를 풀고, ZIP 미리보기 안에서는 실행하지 마세요.
3. 압축을 푼 `SiteCAD` 폴더의 **`Start SiteCAD.cmd`**를 더블클릭합니다. 실행 창이 열리고 PowerShell이 전용 실행 환경을 준비합니다. 관리자 권한은 필요하지 않습니다.
4. 준비가 끝나면 기본 브라우저가 열립니다. 열리지 않으면 실행 창에 나온 `http://127.0.0.1:숫자/` 주소를 사용합니다. 실행 창은 작업 중 유지합니다.
5. **설정 → 일반 → 폴더 선택**과 [AI 연결](#처음-ai-연결)을 진행합니다.

Windows x64에서 설치·실행을 검증했습니다. 웹앱 실행기는 Windows ARM64 경로도 제공하지만 해당 실기기 검증은 수행하지 않았습니다. PowerShell 실행 정책은 이 실행에만 적용하며 시스템 설정을 변경하지 않습니다. 회사 보안 정책으로 실행이 차단되면 담당자에게 허용을 요청하세요.

### 다시 열기와 종료

- **다음 실행:** 같은 폴더의 `Start SiteCAD` 파일을 다시 실행합니다. 실행기가 이미 켜져 있으면 기존 서비스에 다시 연결합니다.
- **브라우저만 닫은 경우:** 실행 창이 살아 있으면 같은 로컬 주소로 돌아가거나 실행 파일을 다시 엽니다. 브라우저 탭을 닫는 것만으로 서버가 종료되지는 않습니다.
- **종료:** 필요한 도면을 **DWG 저장**한 뒤 상단 **실행기 종료**를 누릅니다. 터미널을 닫거나 `Control+C`로 중단해도 서비스가 끝날 수 있으므로 저장을 먼저 하세요. PC 종료·재부팅 후에는 실행 파일을 다시 열어야 합니다.
- **다른 브라우저로 전환:** **이 브라우저로 연결**을 사용합니다. 진행 중인 작업을 마치고 열린 도면을 모두 저장해야 하며 도면 작업 권한은 한 탭에만 있습니다. 전환한 화면에서는 저장한 DWG를 다시 여세요. 비정상 종료로 연결이 남으면 권한 만료 후 복구 안내를 사용합니다. 미저장 편집은 다른 브라우저로 옮겨지지 않습니다.

## 데스크탑 설치와 실행

데스크탑 설치 파일에는 Electron, 운영 의존성, Codex 실행 환경이 포함됩니다. **별도 터미널에서 서버를 켜거나 Node.js·Codex CLI를 직접 실행할 필요가 없습니다.** 앱을 열면 내부 로컬 서비스가 시작되고, 앱 종료 시 관련 작업을 정리합니다. AI 로그인과 외부 연결은 설치 후 각 사용자가 설정합니다. 선택 기능인 Claude Console용 `ant` CLI와 KCSC 전용 환경까지 미리 포함하는 것은 아닙니다.

현재 설치 파일은 배포자 인증서로 **서명·공증하지 않았습니다.** 운영체제의 출처 확인 절차는 사용자가 직접 진행해야 합니다. Windows ARM64용 데스크탑 설치 검증은 이번 배포 대상에 포함하지 않습니다.

### Mac M계열 — DMG

1. Actions에서 내려받은 ZIP을 풀어 `SiteCAD-0.16.0-macOS-arm64.dmg`를 찾습니다.
2. DMG를 더블클릭하고 창 안의 **`SiteCAD.app`을 Applications(응용 프로그램) 바로가기로 드래그**합니다.
3. 복사가 끝나면 DMG를 추출하고 **응용 프로그램 → SiteCAD**에서 실행합니다. DMG 안의 앱을 계속 실행하는 방식은 사용하지 마세요.
4. macOS가 차단하면 출처를 확인한 뒤 **시스템 설정 → 개인정보 보호 및 보안**에서 표시되는 실행 허용 절차를 진행합니다.
5. 앱 창이 열리면 **설정 → 일반 → 폴더 선택**으로 문서 폴더 등 쓰기 가능한 도면 저장 위치를 선택합니다. `/Applications`에 설치한 경우 기본 도면 경로는 `/Applications/drawings/`이므로 계정에 따라 저장 권한이 없을 수 있습니다.
6. [AI 연결](#처음-ai-연결)을 마치고 도면을 열거나 새 도면을 만듭니다. 종료 전에는 DWG를 저장하고 앱의 종료 확인 창을 확인합니다.

### Windows x64 — Setup.exe

1. Actions에서 내려받은 ZIP을 풀어 `SiteCAD-0.16.0-Windows-x64-Setup.exe`를 찾습니다.
2. 설치 파일을 실행합니다. 출처 확인 경고가 나타나면 GitHub 저장소와 받은 파일을 확인하고 운영체제 안내에 따라 진행합니다.
3. 설치 마법사에서 라이선스와 설치 위치를 확인합니다. 기본 경로는 **`%LOCALAPPDATA%\Programs\SiteCAD`**이며 현재 사용자 계정에 설치하므로 관리자 권한이 필요하지 않습니다.
4. 설치 후 **시작 메뉴 또는 바탕 화면의 SiteCAD**를 엽니다. 별도 실행 창을 유지할 필요는 없습니다.
5. **설정 → 일반 → 폴더 선택**에서 도면 위치를 확인하고 [AI 연결](#처음-ai-연결)을 진행합니다. 기본 도면 위치는 설치 폴더의 `drawings/`입니다.

## 처음 AI 연결

도면 화면에서 상단 **⚙ 설정 → LLM**을 엽니다. 웹앱에서는 설정 버튼이 **저장 폴더** 왼쪽에 있습니다. 웹앱과 데스크탑의 로그인·설정·대화 기록은 별도로 보관되므로 한쪽에서 연결해도 다른 쪽에 자동 적용되지 않습니다.

| 연결 | 등록 방법 | 사용 조건 |
| --- | --- | --- |
| OpenAI · ChatGPT OAuth | **ChatGPT로 로그인** 또는 상단 **ChatGPT로 계속**에서 브라우저 인증 | 계정에 허용된 Codex 모델·사용 한도 적용 |
| OpenAI · API 키 | [OpenAI API 키](https://platform.openai.com/api-keys)를 발급해 해당 연결의 비공개 입력란에 입력 → **키 저장** | API 실행 권한·잔액·사용 한도 별도 확인 |
| Claude · Anthropic API 키 | [Claude Console API 키](https://platform.claude.com/settings/keys)를 발급해 입력 → **키 저장** | API 과금 연결, 필요하면 Workspace ID 입력 |
| Claude · Console OAuth | 설정의 공식 설치 안내에 따라 `ant` 설치 → **Claude Console로 로그인·다시 확인** | 공식 CLI의 Console 인증 사용; Claude Pro·Max 구독 연결이 아님 |

등록 뒤 **이 연결 사용 → 모델 목록·연결 확인 → 모델 목록 불러오기 → 모델 선택 → 선택 모델 적용** 순서로 진행합니다. 연결 확인은 모델 목록에 접근할 수 있는지 검사하며, 실제 답변 생성 권한·잔액까지 보증하지 않습니다. 키를 일반 채팅에 붙여 넣지 마세요. 작업 중에는 공급자·키·외부 연결을 변경할 수 없습니다.

CAD 화면이 준비되고 AI 연결을 마치면 빈 채팅의 **“높이 2m 콘크리트 옹벽 도면 만들어줘”**, **“물량 검증해줘”**, **“설계기준 맞는지 확인해줘”** 중 하나를 누르거나 원하는 요청을 직접 입력합니다. 예시를 누르면 입력창에 들어가므로 내용을 확인한 뒤 전송하세요.

## 업데이트·백업·삭제

1. 기존 버전에서 열린 도면을 모두 저장하고 **DWG와 함께 생성된 `.sitecad.json` 보조 파일**을 백업합니다. 저장 폴더를 별도로 지정했다면 그 위치를 확인하세요.
2. 웹앱은 **실행기 종료**, 데스크탑은 앱 종료로 기존 버전을 완전히 닫습니다. 두 버전으로 같은 도면을 동시에 편집하지 마세요.
3. **웹앱:** 새 ZIP을 기존 폴더에 덮어쓰지 말고 새 폴더에 풉니다. 기본 `drawings/`를 사용했다면 기존 도면·보조 파일을 새 폴더로 복사하거나 설정에서 기존 저장 폴더를 선택합니다. 별도로 지정한 저장 위치는 사용자 설정에 남습니다.
4. **Mac 데스크탑:** 새 DMG의 `SiteCAD.app`으로 응용 프로그램의 기존 앱을 교체합니다. **Windows 데스크탑:** 새 Setup.exe를 실행해 기존 설치 위치를 선택합니다. 앱 내부 파일만 따로 옮기지 마세요.
5. 새 버전을 열어 AI 연결·저장 위치를 확인하고 백업한 도면을 엽니다. 웹앱과 데스크탑 사이에는 설정을 자동 이전하지 않습니다. 다른 PC에서는 인증 정보를 새로 등록하세요.

Windows 데스크탑 제거는 **설정 → 앱**의 SiteCAD 제거 기능을 사용합니다. Mac은 종료 후 `SiteCAD.app`을 휴지통으로 옮깁니다. 사용자 도면과 별도 사용자 데이터 폴더는 앱 제거와 구분해 관리합니다. 웹앱도 실행기를 종료한 뒤 프로그램 폴더를 지우면 그 안의 기본 `drawings/`까지 지워지므로, 먼저 도면을 다른 곳으로 옮기세요. 자동 업데이트 기능은 제공하지 않습니다.

## 통합 설정

상단 **⚙ 설정**에서 일반·LLM·API·MCP·플러그인을 관리합니다. **일반 → 도면 저장 폴더 → 폴더 선택**을 누르면 macOS·Windows의 폴더 선택 창이 열립니다. 선택한 폴더를 쓰기 권한 확인 후 적용하고, 취소하면 기존 위치를 유지합니다. 기본 도면 경로는 웹앱과 데스크탑이 다르므로 [데이터와 보안](#데이터와-보안)의 표를 확인하세요. 기본 폴더는 처음 저장하거나 폴더를 열 때 생성합니다. 기존에 직접 지정한 폴더는 유지하며 **기본 폴더로 되돌리기**로 변경할 수 있습니다. 위치는 재실행 후에도 유지하며 기존 도면을 이동하지 않고 다음 저장부터 적용합니다.

도면과 채팅 사이 경계를 드래그하면 채팅 너비를 조절할 수 있으며, 경계에 초점을 두고 방향키로도 조절합니다. 같은 화면에서 접었다 다시 열어도 조절한 너비를 유지합니다. 앱 재시작 후의 너비 복원은 제공하지 않습니다.

- **LLM**: 기존 ChatGPT OAuth와 OpenAI API 키, Claude API 키, Claude Console OAuth 중 사용할 연결을 선택합니다. API 키는 제공자의 공식 콘솔에서 직접 발급하고 전용 비밀번호 입력란에 저장합니다. 저장 후 **이 연결 사용 → 모델 목록·연결 확인 → 모델 목록 불러오기 → 선택 모델 적용** 순서로 진행합니다. 모델 목록 조회 성공과 실제 추론 권한·잔액은 별개입니다.
- **Claude Console OAuth**: [Anthropic 공식 CLI 설치 안내](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/quickstart)에 따라 `ant`를 설치한 뒤 **Claude Console로 로그인·다시 확인**을 누릅니다. 공식 `ant auth login --profile sitecad`가 브라우저 인증을 처리하며, SiteCAD 전용 설정 디렉터리를 사용합니다. **Claude Pro·Max 구독 연결이 아니라 Console API 과금 연결**입니다. 앱은 구독 토큰을 추출하거나 로그인 화면·비밀번호를 대신 수집하지 않습니다.
- **API**: 채팅에서 공식 문서·발급 주소와 등록을 요청하면 검토·승인 후 설정에 항목을 만듭니다. 사용자는 해당 사이트에서 발급받은 키를 설정의 비공개 입력란에 저장합니다. VWorld·KCSC는 실제 조회 도구에 연결하며, 일반 API는 키 보관과 호출 기능 미구현을 구분해 표시합니다. 인증이 필요한 MCP의 환경 변수·HTTP Bearer 키도 이 탭에서 등록합니다.
- **MCP**: 채팅에 지원되는 GitHub/npm 패키지 또는 HTTPS MCP 주소와 설치 요청을 입력합니다. 고정 버전·실행 정보와 권한을 검토·승인하고, 설정에서 결과·연결 상태를 관리합니다. 키가 필요한 설치는 실행 대기로 보관하며 설정 → API에서 키를 등록한 뒤 MCP 탭에서 실제 연결을 확인합니다. stdio 환경 변수·HTTP Bearer 외의 인증과 외부 MCP 자체 OAuth는 자동 지원하지 않습니다.
- **플러그인**: GitHub의 OpenAI·Claude 형식 매니페스트와 전체 지침을 검토하고 승인한 독립적인 `SKILL.md` 묶음만 설치합니다. 실행 코드·훅·부속 파일·앱·MCP 의존성을 가진 네이티브 플러그인의 전체 설치 기능은 아닙니다.

OpenAI API는 Responses API, Claude는 Messages API를 사용하며 기존 CAD 도구와 실행 승인·도면 저장 검사를 공유합니다. API 연결은 현재 대화의 텍스트 기록을 보내고 도구 진행 상태와 최종 답변을 표시합니다. 토큰 단위 출력과 Codex 내장 웹검색은 API 연결에서 제공하지 않으며, 문서 fetch·기존 조사 도구·등록한 MCP를 사용할 수 있습니다. 작업 중에는 공급자·키·외부 연결을 변경하지 못합니다.

키는 로컬 웹앱의 운영체제 키체인 기반 암호화 저장소 또는 데스크탑 앱의 기존 보안 저장소에 보관합니다. 키 원문은 공개 상태 응답·채팅 기록·설정 목록에 포함하지 않습니다. LLM에 보낸 도면 맥락·대화·도구 결과는 선택한 제공자의 온라인 서비스로 전송됩니다. Claude OAuth 갱신 정보는 공식 CLI가 전용 프로필에서 관리합니다.

## 할 수 있는 작업

- DWG 열기, 기본 2D 작도, 객체 이동·삭제, 치수·한글 주석 작성, 레이어별 객체 조회와 측정
- 엔진의 명령 검색·실행 및 후속 입력을 AI가 판단해 진행
- 기존 범용 연결로 레코드 속성·레이어·선종류·문자/치수 스타일 수정, 블록 정의·삭제, 배치 생성·전환·페이지 설정과 제한된 시스템 변수 조정
- 기존 범용 연결로 3D 기본 입체, 돌출·회전·스윕·로프트, 합집합·차집합·교집합, 3D 변환·선·면·메쉬와 표준 방향·음영 보기 명령 실행
- 레이어별 객체 수·길이·폐합 면적을 물량 표로 표시
- 웹검색·문서 fetch, 공개 자료 다운로드와 계산을 설계 참고에 활용
- VWorld 주소·필지 조회, 좌표계 변환과 실척 삽입
- 등록된 SHP/GeoJSON 등고선·표고를 필지와 같은 기준으로 삽입
- 주소만으로 필지·공개 등고선을 확보하는 자동 경로: **현재 경기도 광주시 제공 범위**
- 명시적으로 등록·신뢰한 외부 MCP 연결
- 도면 변경 감지, 저장 감사와 누락 검사, 검증된 DWG의 보관·다운로드

예: “6000×4000mm 사각형을 그리고 한글 주석과 가로 치수를 넣어 DWG로 저장해줘.”

2D·3D 범용 연결은 기존 `cad_discover`·`cad_query`·`cad_control`을 사용하며 기능별 새 도구를 만들지 않습니다. 설치된 엔진의 `record_schema`와 실제 `records`를 조회한 뒤 `set_properties`로 현재 값과 일치할 때만 수정합니다. 엔진에 존재하는 명령과 현재 웹 빌드에서 실행 가능한 명령을 구분하고, 한글 이름·후속 입력·명령 완료 상태를 처리합니다. `STYLE`·`DIMSTYLE`은 대화상자를 열지 않는 `LIST`·`NEW` 형식만 허용하며 지원되는 설정 변경은 시스템 변수와 레코드 속성을 사용합니다.

물량 검증 요청은 기본 `quantity-review` 절차를 읽고 진행합니다. 단위 미지정 DWG도 문자·블록 속성·원시 형상과 길이를 조회할 수 있으며, 환산 배율은 모르면 `null`입니다. 사용자가 확인한 단위는 계산에 명시적으로 적용하고 DWG 단위를 자동 변경하지 않습니다. 철근은 **기호 → 명시된 직경 → 가공길이·본수 → 산출표 행**을 근거 핸들과 함께 연결해 일치·불일치·미확인을 구분합니다. 상세도 축척·블록 배율·반복 표현을 확인하며, 치수선·대표 가공선·같은 철근의 여러 뷰를 중복 합산하지 않습니다. 기존 레이어별 `quantity_review` 집계는 블록 내부·배치를 제외하므로 철근 검증 완료의 근거가 아닙니다. 해석이 모호하거나 표가 없으면 전체 적정 판정을 보류합니다.

3D도 같은 명령 검색·실행·후속 입력 경로를 사용합니다. 예: “6000×4000×3000mm 박스를 만들고 원기둥을 빼서 구멍을 낸 뒤 체적을 확인하고, 등각 음영 보기로 DWG 저장해줘.” `Solid`는 2D 채움 면이며 `entities_create`에 `Solid3D`를 넣지 않습니다. 입체는 `BOX`·`EXTRUDE` 등 실제 지원 명령으로 생성합니다. 높이가 변하는 폴리선은 Z를 무시하는 `LwPolyline` 대신 `3DPOLY`를 사용합니다. 3D 회전·대칭·정렬은 해당 3D 명령을 사용하고, `VIEW SWISO` 같은 정해진 보기와 `VISUALSTYLES`의 7개 표시 모드만 실행합니다. `3DORBIT` 마우스 회전 모드와 미구현 `VPOINT`는 LLM에 열지 않습니다. `SOLIDEDIT`는 현재 엔진의 셸 편집 경로이며 AutoCAD의 모든 솔리드 편집 옵션을 뜻하지 않습니다. 체적·표면적 측정값은 각각 도면 단위의 세제곱·제곱이며, 값이 없으면 미지원으로 보고합니다. 프로파일·불리언 작업은 원본을 지울 수 있고 형상에 따라 거부될 수 있으므로 결과 객체·측정값을 확인합니다. 레이어별 물량 표는 기존 2D 집계이며 3D 체적 표로 자동 확장되지 않습니다.

블록은 실제 조회한 객체를 대상으로 정의하며 강제 삭제는 해당 블록을 참조하는 삽입 객체도 지울 수 있습니다. 배치 방향을 변경할 때는 용지 이름과 방향을 함께 지정합니다. 배치·페이지 설정은 기존 엔진 기능을 이용하지만 **웹 빌드의 `plot`·`wblock` 파일 출력은 native-only로 지원하지 않습니다. 페이지 설정 성공이 PDF 출력 성공을 뜻하지 않습니다.** 도면 식별자·수정 상태·좌표 단위·선택 변경 검사와 지리 기준 보호, 전용 DWG 저장 검증은 유지합니다.

VWorld 키는 **설정 → API → VWorld**에서 등록합니다. 채팅에 `/api vworld`를 입력하거나 키가 없는 상태에서 주소·필지 조회를 요청하면 해당 설정을 안내합니다. 등록 후 원래 요청을 다시 전송하세요. 키를 일반 채팅 본문에 입력하지 마세요. 저장소와 배포 파일에는 키가 없습니다. SHP는 같은 이름의 SHP·DBF·PRJ를 함께 선택합니다. 외부 MCP 호출은 서버·도구·인수를 표시하고 1회 승인 또는 거절을 받습니다.

## 채팅·외부 연결·스킬

외부 연결은 통합 설정에서 관리합니다. API·MCP·플러그인 추가는 채팅에서 URL과 자연어로 요청하고, 설정은 설치 결과·연결 상태·비공개 키를 관리합니다. 내부 CAD·웹검색·계산·지형 처리와 KDS/KCS 검색 안내는 별도 연결로 나열하지 않습니다. 개발용 REA 기본 연결과 패키지는 제외했습니다.

**스킬목록(/)**은 스킬만 표시합니다. 플러그인에 포함된 스킬도 같은 목록에서 실행합니다. 설정에서는 API의 **키 미등록**과 **키 등록됨**을 실제 조회 성공 여부와 구분합니다. 키가 없는 VWorld 연결에는 `/api vworld` 등록 안내를 표시합니다.

KCSC 기준 조회 MCP는 채팅에 `/api kcsc` 또는 “KCSC MCP 연결해줘”라고 요청해 등록합니다. [국가건설기준센터 API 안내](https://kcsc.re.kr/support/api)에 로그인한 뒤 **인증키 발급신청**으로 개인 키를 발급받고, 설정 → API → KCSC의 비밀번호 입력란에 입력하세요. 등록·실행을 승인하면 고정 버전의 전용 실행 환경을 준비하고 키를 SiteCAD의 암호화된 MCP 비밀 저장소에 보관합니다. 키 저장·교체·삭제와 실제 연결 확인은 같은 설정 항목에서 진행합니다. 다른 사용자의 설치본에는 이 사용자의 키가 포함되지 않습니다.

KCSC 전용 실행 환경 자동 설치는 **Apple Silicon Mac과 Windows x64·ARM64**를 지원합니다.

예: “등록된 kcsc MCP로 콘크리트 습윤 양생 기간을 관련 기준과 조항까지 찾아줘.” 기준 명칭·코드는 `kcsc_search`, 지정 기준 본문은 `kcsc_grep`·`kcsc_read`로 조회하고 `domain=전체`를 사용합니다. 실제 기준 코드·개정 정보·조항·표와 원문 조건을 확인하며 자동 분류와 참조 감사만으로 설계 적합성을 보증하지 않습니다. 설계 flow와 design 도구는 기본 조회 범위에 포함하지 않고 외부 도구 호출 승인 정책을 유지합니다.

채팅의 **모델** 버튼 또는 설정 → LLM에서 **사용 중인 연결의 모델 목록**을 조회하고 다음 요청의 모델을 선택합니다. ChatGPT OAuth는 고정 Codex 버전의 카탈로그를, API·Claude 연결은 해당 제공자의 모델 목록을 사용합니다. 카탈로그 표시는 계정별 실행 권한을 보증하지 않으며, 실제 요청에서 확인합니다. 모델 선택은 현재 화면에 유지합니다. 도구 진행 상태와 답변을 표시하며 토큰 단위 스트리밍 여부는 연결 방식에 따라 다릅니다. 처리 과정은 기본 접힌 큰 묶음으로 제공하고 펼친 경우에만 개별 내용을 확인하며, 승인 요청은 바로 표시합니다. 완료된 과정은 현재 응답에 접힌 기록으로 남기고, 기존 도면 변경 감지·저장 검증을 통과한 최종 응답만 완료 처리합니다. 내부 추론이나 비밀 도구 인수·결과는 진행 영역에 표시하지 않습니다. 연결이 끊기면 작업을 취소하고 부분 결과를 확인하도록 안내하며 자동 재실행하지 않습니다.

0.16.0에서는 AI 작업 중에도 같은 입력창에 보충·수정할 내용을 쓰고 **추가 지시**로 실행 중인 작업에 전달할 수 있습니다. 수락된 지시는 같은 채팅 기록에 남습니다. 작업이 끝나기 직전이면 전달이 거절될 수 있으며, 이때 입력은 유지됩니다. **정지**는 이후 실행을 중단하고 미완료 명령을 정리하지만 이미 반영된 객체를 자동으로 되돌리지 않습니다. 스킬·연결 등록 안내는 입력창 아래에 있으며, 스킬 실행과 MCP/API 등록은 현재 작업을 마친 뒤 요청합니다.

ChatGPT OAuth에서 사용하는 Codex 0.163.0의 번들 카탈로그는 11개 중 표시 대상 8개를 제공합니다. 웹검색 도구가 유지되도록 전체 메타데이터를 보존한 채 `use_responses_lite:false`로 생성합니다. 이 수치는 API·Claude 모델 목록의 개수를 뜻하지 않습니다. Codex 버전을 변경하면 `node scripts/update-model-catalog.mjs`로 같은 실행 파일의 카탈로그를 다시 생성하고 모델·웹검색 회귀를 확인합니다.

채팅 패널 경계의 **화살표**로 접고 엽니다. **새 채팅**과 기록 선택으로 대화를 나누고, **삭제 → 삭제 확인**으로 선택한 채팅 기록만 삭제합니다. 마지막 기록을 삭제하면 빈 채팅을 만듭니다. 빈 채팅에만 시작 예시 세 개를 표시하며 클릭하면 입력창에 들어갑니다. 대화별 Codex 스레드를 따로 저장하고 재실행 시 복원하며, 대화 본문은 SiteCAD 전용 `chat-sessions/`에 보관합니다. 채팅을 바꿔도 현재 CAD 도면은 유지됩니다. 이전 대화의 객체 핸들이 현재 도면과 일치한다고 가정하지 않습니다. 기록의 텍스트에 포함된 표는 다시 표시하지만 별도 물량 보고서·출처 카드·다운로드 링크·처리 과정은 다시 구성하지 않습니다. 채팅은 최대 100개, 채팅당 메시지 500개까지 보관합니다.

물량·기준 검토의 표 형식 답변은 채팅창에서 실제 표로 표시합니다. 실시간 응답과 과거 채팅에도 적용하며 좁은 패널에서는 표를 가로로 스크롤합니다. 결과가 원하는 내용과 다르면 답변 아래 **원하는 결과가 아닌가요? → 처리 방법 알려주기**를 눌러 다른 점과 원하는 절차를 작성해 보내세요. AI는 부족한 처리 규칙을 확인하고 정리한 절차의 스킬 등록 여부를 묻습니다. 실패만으로 스킬을 자동 저장하거나 앱·MCP 코드를 수정하지 않습니다. 기존 스킬 덮어쓰기 승인도 유지합니다.

- `/mcp`: 설정 → MCP 안내로 연결합니다. 별도 설치 폼은 만들지 않으며 주소와 설치 요청은 채팅에서 전달합니다.
- GitHub MCP URL과 “설치해줘”: 공개 저장소·고정 커밋과 npm 배포 원본·버전·SHA-512를 확인한 뒤 정확한 실행 파일과 인수를 승인받습니다. 범용 자동 설치 대상은 같은 GitHub 저장소를 표시하는 **npm 배포 Node MCP**입니다. KCSC는 위의 전용 Python 설치 경로를 지원합니다. 다른 소스 빌드·Python MCP·임의 셸 설치 명령은 지원하지 않으며 필요한 별도 실행 환경은 수동 설정합니다. npm 설치 스크립트는 실행하지 않습니다.
- HTTPS MCP 주소와 “연결해줘”: 승인 후 SiteCAD 전용 설정에 등록합니다. 필요한 인증값은 설정 → API의 해당 MCP 비공개 입력란에 등록합니다.
- 공식 문서 URL과 “API 등록해줘”: LLM이 발급 안내와 API 항목을 준비하고, 사용자는 설정에서 키를 입력합니다. `/api vworld`·`/api kcsc`는 기존 조회 기능의 설정으로 연결합니다. 일반 API는 메타정보와 키를 보관하지만 실행 연결을 자동 생성하지 않습니다. 모델에 키를 전달하거나 자동 스크립트를 실행하지 않습니다.
- 공개 GitHub 플러그인 URL과 “설치해줘”: 고정 커밋의 매니페스트와 전체 지침을 확인하고 승인 후 SiteCAD 전용 스킬로 설치합니다. **현재 지원 범위는 부속 파일이 없는 독립적인 SKILL.md 묶음**입니다. MCP·앱·훅·실행 스크립트·참조 파일을 포함한 플러그인은 설치하지 않고 미지원 이유를 알려줍니다. 설치된 작업은 `/plugin-플러그인이름-스킬이름 요청` 또는 **스킬목록(/)** 목록으로 실행하고 설정 → 플러그인에 표시합니다. Codex 마켓플레이스 플러그인의 모든 기능을 설치하는 방식은 아닙니다.
- “지형 원본 등록해줘”: 채팅 카드에서 SHP·DBF·PRJ 또는 GeoJSON을 선택합니다.
- “지금까지 작업을 `site-check` 스킬로 만들어줘”: 현재 대화의 작업을 재사용 가능한 지침으로 저장합니다. **스킬목록(/)** 목록에서 선택하거나 `/site-check 요청 내용`으로 실행합니다. ChatGPT OAuth에서는 Codex 네이티브 `skill` 입력으로, OpenAI API·Claude 연결에서는 같은 `SKILL.md` 본문을 AI 지침에 포함해 전달합니다. 기존 스킬 수정은 원문 해시 확인과 덮어쓰기 승인이 필요합니다.

`skill-creator`·`skill-finder`·`skill-installer`를 기본 제공합니다. SiteCAD 관리 도구에 맞춘 번들 지침이며 외부 마켓플레이스 패키지를 설치한 것으로 표시하지 않습니다. 기본 스킬은 첫 실행에 `codex-home/skills/`에 준비하며 사용자 스킬을 덮어쓰지 않습니다. `skill-finder`는 설치된 스킬을 검색하고, 외부 후보 조사는 웹검색으로 진행합니다. `skill-installer`는 검토한 지침을 SiteCAD 스킬로 저장하며 임의 저장소의 스크립트를 실행하지 않습니다.

설치 승인은 프로그램의 지속적인 등록·실행에 대한 동의입니다. 외부 MCP는 운영체제 사용자 권한으로 실행되며 Codex의 읽기 전용 샌드박스와 별개입니다. 설치·등록은 현재 채팅 작업 종료 후 적용하고 실제 MCP 도구 목록을 확인한 경우만 연결 완료로 표시합니다. 인증 키가 필요하면 실행 대기로 보관하고, 그 밖의 연결 실패는 새 등록을 되돌려 기존 설정을 보존합니다. 성공·실패 결과는 설정의 설치 기록에 남깁니다. 추가한 서버는 다음 메시지부터 사용할 수 있으며 이후 외부 도구 호출에는 기존 1회 승인이 계속 적용됩니다.

3D 측정의 `mesh.volume`·`mesh.surface_area`는 삼각형으로 나눈 형상의 근사값이며 DWG를 다시 열면 분할 정밀도에 따라 달라질 수 있습니다. 정확한 커널 질량 특성으로 표시하지 않습니다. 현재 엔진은 재개방한 일부 ACIS 입체의 경계를 0으로 반환하므로 이 값은 위치·정렬 검증에 사용할 수 없습니다. 로컬 검증에서는 저장한 동일 DWG를 AutoCAD에서 열어 실제 솔리드 체적·좌표와 `AUDIT`를 별도로 확인했습니다.

전국 지형 자동 확보, 로그인 포털 자료의 자동 다운로드, DEM 래스터·지표면 메쉬, 스캔/지도 이미지 형상 추출, 구조 설계 적합성 판단, 별도 파라메트릭 3D 설계·조립 이력 시스템 및 다중 사용자는 현재 범위에 포함하지 않습니다. 지원 명령 연결이 모든 3D 형상의 호환성을 보증하지는 않습니다. 필지·지형의 출처·좌표계·표고 기준·정확도를 확인해야 하며 공인 측량 경계나 설계 승인을 대신하지 않습니다.

## 데이터와 보안

| 사용 방식 | 사용자 데이터·설정·대화 | 기본 도면 폴더 |
| --- | --- | --- |
| Mac 웹앱 | `~/Library/Application Support/SiteCAD Web/` | 압축을 푼 `SiteCAD/drawings/` |
| Windows 웹앱 | `%LOCALAPPDATA%\SiteCAD Web\` | 압축을 푼 `SiteCAD\drawings\` |
| Mac 데스크탑 | `~/Library/Application Support/SiteCAD/` | `SiteCAD.app`이 있는 폴더의 `drawings/`; 응용 프로그램에 설치했다면 `/Applications/drawings/` |
| Windows 데스크탑 | `%APPDATA%\SiteCAD\` | 설치 폴더의 `drawings\`; 기본 설치는 `%LOCALAPPDATA%\Programs\SiteCAD\drawings\` |

- 도면 위치는 **설정 → 일반 → 폴더 선택**에서 변경합니다. 위 표는 기본값이며 이미 선택한 경로가 있으면 그 경로를 사용합니다. 선택값은 각 사용자 데이터 폴더의 `drawing-storage.json`에 저장합니다. 기존 도면은 자동 이동하지 않습니다. 위치 기준이 있는 DWG는 함께 저장되는 `.sitecad.json` 보조 파일도 보관하세요. 브라우저가 별도로 내려받는 복사본은 브라우저 다운로드 설정을 따릅니다.
- 앱 전용 `codex-home/`·`workspace/`를 사용하며 기존 Codex 앱·CLI의 설정과 로그인을 수정하지 않습니다.
- 추가 MCP 패키지는 `managed-mcp/`, 스킬과 플러그인 지침은 `codex-home/skills/`, 플러그인 목록은 `plugins.json`, 채팅·Codex 대화 기록은 SiteCAD 사용자 폴더에만 보관합니다. 사용자 스킬·추가 MCP·플러그인·대화·인증 정보는 배포 ZIP에 포함하지 않습니다.
- 웹앱 인증 정보는 macOS 키체인 또는 Windows 자격 증명 관리자에 보관한 키로 암호화합니다. 데스크탑은 Electron의 운영체제 보안 저장소를 이용합니다. 평문 대체 저장은 하지 않으며 암호화된 사용자 폴더를 다른 PC에 복사하는 것만으로 로그인 이전을 보장하지 않습니다.
- 웹앱의 Node 런타임·의존성은 압축을 푼 폴더의 `.runtime/`, `node_modules/`, `runtime/`에 준비됩니다. 웹앱은 Electron을 설치하거나 실행하지 않습니다. 데스크탑은 설치 파일에 포함된 런타임을 사용합니다.
- 로컬 서버는 loopback에만 연결하며 호스트·출처·브라우저 연결 권한을 검사합니다. 하나의 브라우저 탭만 도면 작업을 소유합니다.
- 전체 DWG 파일을 모델에 업로드하지 않지만 채팅 내용·작업에 필요한 객체 문맥과 도구 결과는 AI 요청에 포함됩니다.

회사에서 터미널·자식 프로세스·네트워크 실행을 차단하는 경우 담당자의 허용이 필요합니다. 앱은 해당 정책을 우회하지 않습니다. 저장을 요청하지 않은 편집은 자동으로 디스크에 보존되지 않으므로 중요한 업무 도면은 복사본으로 작업하세요.

## 소스에서 실행·검사·패키징

이 저장소를 내려받은 뒤 Mac은 `Start SiteCAD.command`, Windows는 `Start SiteCAD.cmd`를 실행해도 같은 준비 절차가 동작합니다. 편집기 스냅샷과 예제 도면은 저장소에 포함돼 있습니다. 아래 npm 명령으로 직접 개발할 때는 `package.json`의 Node 조건(`>=22.18.0 <23` 또는 `>=24.2.0`)이 필요하며, 검증·원클릭 실행기 기준 버전은 24.22.1입니다.

```sh
git clone https://github.com/seominpapa/SiteCAD.git
cd SiteCAD
# Windows: Start SiteCAD.cmd / macOS: Start SiteCAD.command 더블클릭
# 개발용 Node를 사용하는 경우:
npm ci
node scripts/install-codex.mjs
npm run local-web
npm test
npm run local-web:build
npm run local-web:build:windows
npm run desktop
npm run desktop:build
```

`npm start`는 초기 구조화 계획기 시제품입니다. 전체 MCP 기능에는 원클릭 실행기 또는 `npm run local-web`을 사용합니다. `npm run desktop`은 개발용 Electron 앱을 실행하고 `npm run desktop:build`는 현재 운영체제의 데스크탑 설치 파일을 만듭니다. Mac M계열은 DMG, Windows x64는 Setup.exe를 생성합니다. Windows 빌드에는 Inno Setup 6.6.1이 필요하며 `INNO_SETUP_COMPILER`로 `ISCC.exe` 위치를 지정할 수 있습니다. 일반 사용자는 빌드 명령 대신 위의 설치 파일을 사용하세요.

웹앱 ZIP은 명시된 소스·잠금 파일·편집기 스냅샷·라이선스·예제만 포함합니다. 사용자 인증·API 키·개인 도면·실행 캐시·설치된 의존성은 제외합니다. Node와 Codex 다운로드는 고정 SHA-256으로 검증합니다. 데스크탑 설치 파일에는 실행에 필요한 의존성과 런타임도 포함합니다. 공개 릴리스에 `SHA256SUMS.txt`가 첨부된 경우 해당 릴리스 파일의 무결성을 확인할 수 있으며, 다른 빌드의 파일에는 그 해시를 적용하지 마세요.
